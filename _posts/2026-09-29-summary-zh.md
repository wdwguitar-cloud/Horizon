### [Anthropic 发布 Claude Sonnet 5.5 引发基准与定价讨论](https://www.anthropic.com/claude-sonnet-5-5) ⭐️ 8.0/10

Anthropic 正式发布 Claude Sonnet 5.5，官方公告在 Hacker News 上获得 637 分和 429 条评论，讨论主要围绕模型能力、基准测试的注意事项和成本竞争。社区评论提到，Sonnet 5.5 在 Terminal-Bench 上得分 70.6，高于 Opus 5.5 的 66.4，但 Opus 5.5 约有 10% 的试验因安全防护由回退模型回答，而 Sonnet 5.5 仅约 1.5%，因此这一差距未必可直接解释为能力超越。Anthropic 表示 Sonnet 5.5 的网络能力较 Sonnet 5 大幅提升，所以采用与 Opus 5.5 类似的安全防护，高风险网络安全任务会明显回退到 Sonnet 5。另有评论指出，其价格比常用的中国模型贵约 20 倍，GLM 和 DeepSeek 等模型在非前沿任务上已具备很强的价格竞争力。

hackernews · D2OQZG8l5BI1S06 · 9月28日 17:58 · [社区讨论](https://news.ycombinator.com/item?id=49881850)

**「背景」** Claude Sonnet 是 Anthropic 面向编码与 agent 类任务的中端模型系列，定位低于旗舰 Opus 系列；官方称上一代 Sonnet 5 的性能已接近 Opus 4.8，同时价格更低。Sonnet 5.5 沿用 Sonnet 5 的定价，即每百万输入 token 2 美元、每百万输出 token 10 美元，Anthropic 称其输出生成速度提升逾 30%，测试中每任务成本最多降低 30%。在衡量终端与编码 agent 能力的 Terminal-Bench 4.0 上，Sonnet 5.5 得分 70.6%，并附带五项破坏性 API 变更。

**「影响」** 对使用 Claude API 的开发者而言，Sonnet 5.5 以每百万输入 token 2 美元、输出 10 美元、100 万 token 上下文和最高 12.8 万输出 token 的规格直接接替 Sonnet 5，可将日常编码等任务迁移到成本更低的 Sonnet 层级。不过其评测表现受高风险管理回退影响（社区指出 Opus 5.5 的 Terminal-Bench 试验约 10% 由回退模型作答，而 Sonnet 5.5 约 1.5%），实际收益仍需按具体任务验证。

**「社区讨论」** 评论既有对基准可解释性的质疑，也有实际使用体验：有人指出 Opus 5.5 因安全回退导致 Terminal-Bench 成绩偏低，因此 Sonnet 5.5 反超不应过度解读；也有用户表示 Opus 5.5 在 5x 套餐下已够日常使用，不清楚何时会需要 Sonnet 5.5。成本是另一大分歧点，有评论者称在非前沿场景下更倾向使用 GLM、DeepSeek 等中国模型，因为 Sonnet 5.5 的价格可高出约 20 倍。

### [Jeff：兼容 Jev 的 0.8B 决策模型，约 30 毫秒延迟](https://github.com/firelex/jeff) ⭐️ 7.0/10

Hacker News 上，作者 firelex 发布了 GitHub 项目 Jeff，提供兼容 Jev 的 0.8B 决策模型，称在家中训练并实现约 30 毫秒延迟。该模型面向设备端推理与分类等小模型工作负载，因而引发关于准确性和端侧可部署性的讨论。评论中有人称在自己的用例里与 Jev 相比准确率为 70% 对 94%，认为用于分类不可接受；也有人提到在某个评测面板上为 83.1 对 83.0。由于缺少可获取的源内容，项目细节、训练硬件配置以及在手机 NPU 等设备上的实际表现尚未明确。

hackernews · firelex · 9月28日 20:23 · [社区讨论](https://news.ycombinator.com/item?id=49883844)

**「背景」** Jev 是 TypeSafe AI 推出的零样本分类模型：它在收到请求时把文本分配到调用方给出的标签上，并为每个标签输出概率，因此不需要针对具体类别重新训练。Jeff 最初是 Denis Yarats 的开源配方 AutoJev（MIT 许可）的分支，AutoJev 通过微调 Qwen 模型来输出 Jev 风格的判定；Jeff 保留了其核心设计——每次判定一次前向传播、训练过的答案读出、为校准而拟合的温度——并在此基础上扩展到 Qwen 与 Gemma 的小型学生模型（0.8B、2B）、带泄漏过滤的本地合成数据管线，以及 Apple 芯片上的 MLX 推理。作为参照，Jev 在 Banking77 的 77 类意图分类任务上零样本得分 80.1%，明显高于经典零样本 NLI 基线的 48.8%。

**「影响」** 对于考虑在分类或端侧场景中用 Jeff 替代 Jev 的开发者，社区实测给出的 70% 对 94% 准确率差距意味着它目前尚不足以作为直接替代品；而其能否真正上机，还取决于 0.8B 模型在手机 NPU 上而非评测所用 M4 Max 上的延迟与内存表现，这一点尚未被验证。此外，此类模型通常需要针对 NPU 专门优化并在有限内存（如 6 GB RAM 手机）约束下运行，因此“约 30 ms”的延迟数值并不能直接外推到设备端部署。

**「社区讨论」** 评论整体认可在家训练 0.8B 模型并达到约 30 毫秒延迟的技术难度，但核心分歧在准确性：有用户报告实际分类任务中 70% 对 Jev 94%，认为不可接受，也有人指出评测面板 83.1 对 83.0 与真实用例差距说明零样本分类波动大。讨论还追问训练硬件、手机 NPU 与 M4 Max 的部署差异，以及分类需求对企业 AI 支出和数据中心使用的影响。
